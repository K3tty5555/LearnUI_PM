# UI 词典动态标本恢复

2026-09-07：用户明确指出控件动效是核心能力，不能为性能优化替换成静态图。

## 实现

- UI 词典的全部 78 个控件重新使用原始 HTML/CSS/JS，在目录自动呈现动效。
- 每个标本在隔离的演示帧中运行；进入视口附近 100px 时挂载，离屏或筛选隐藏时移除帧，浏览器同时停止其动画、定时器和监听器。
- 页面进入后台时停止所有标本，回来后恢复；切换语言与减少动态效果偏好时重新初始化可见标本。
- 前三个标本的代码随首页提供，不等待额外请求。首次绘制使用无脚本的原始 HTML，演示帧就绪后接管。
- 其它标本从 api/specimens/ 按需加载，本页内复用已下载的内容；失败状态明确可见，网络恢复后重试。
- 现有玻璃主题、详情交互、搜索、参考集及访问过的资源缓存策略保留。没有恢复整站预下载。

## 实测

浏览器回归覆盖：

- 文本乱序内容随时间改变。
- 弹簧和缓动控件的位置随时间改变。
- 进度条数值随时间增长。
- 滚出视口后原演示帧已移除；筛选剩一个控件时只运行一个演示。
- 后台暂停、语言切换、减少动态效果设置有效。
- 390px 手机端弹簧动效正常，无横向溢出。
- 全部 78 个标本逐一挂载成功，没有 JavaScript 异常。
- 模拟请求失败后，恢复网络可重新加载动效。

本地 1440×1000、150ms 延迟、200 KiB/s 下载、CPU 4 倍降速的单次实验：FCP 约 712ms，LCP 约 760ms，首个动态演示就绪约 2166ms。动效就绪单独计时，不能把主文档 LCP 当作动效启动时间。公网首次连接延迟仍受 GitHub Pages 线路影响。

## 防回归

`scripts/verify-performance.py` 验证所有 UI 动态入口与前三个内嵌标本都存在，同时限制根文档体积、禁止直接启动全部帧以及禁止整站预取。

`scripts/test-live-demos.py` 用真实浏览器检查上述行为，已加入 GitHub Actions。发布前必须通过实际的动效变化测试，不能只检查存在图片或 DOM。
