# UI 词典动态标本恢复

2026-09-07：用户明确指出控件动效是核心能力，不能为性能优化替换成静态图。

## 实现

- UI 词典的全部 113 个控件重新使用原始 HTML/CSS/JS，在目录自动呈现动效。
- 每个标本在隔离的演示帧中运行；进入视口附近 100px 时挂载，离屏或筛选隐藏时移除帧，浏览器同时停止其动画、定时器和监听器。
- 页面进入后台时停止所有标本，回来后恢复；切换语言与减少动态效果偏好时重新初始化可见标本。
- 前三个标本的代码随首页提供，不等待额外请求。首次绘制使用无脚本的原始 HTML，演示帧就绪后接管。
- 其它标本从 api/specimens/ 按需加载，本页内复用已下载的内容；失败状态明确可见，网络恢复后重试。
- 现有玻璃主题、详情交互、搜索、参考集及访问过的资源缓存策略保留。没有恢复整站预下载。

## 实测

浏览器回归覆盖：

- 文本乱序内容随时间改变。
- 弹簧和缓动控件的位置随时间改变。
- 进度条数值随时间增长。
- 滚出视口后原演示帧已移除；筛选剩一个控件时只运行一个演示。
- 后台暂停、语言切换、减少动态效果设置有效。
- 390px 手机端弹簧动效正常，无横向溢出。
- 全部 113 个标本逐一挂载成功，没有 JavaScript 异常。
- 模拟请求失败后，恢复网络可重新加载动效。

本地 1440×1000、150ms 延迟、200 KiB/s 下载、CPU 4 倍降速的单次实验：FCP 约 712ms，LCP 约 760ms，首个动态演示就绪约 2166ms。动效就绪单独计时，不能把主文档 LCP 当作动效启动时间。公网首次连接延迟仍受 GitHub Pages 线路影响。

## 防回归

`scripts/verify-performance.py` 验证所有 UI 动态入口与前三个内嵌标本都存在，同时限制根文档体积、禁止直接启动全部帧以及禁止整站预取。

`scripts/test-live-demos.py` 用真实浏览器检查上述行为，已加入 GitHub Actions。发布前必须通过实际的动效变化测试，不能只检查存在图片或 DOM。

## 目录卡片不许被切（2026-11-20）

`scripts/test-catalog-states.py` 在 1440px 和 390px 两种宽度下，让全部目录卡片各自完整播放一圈（默认 55 秒，覆盖最长的「高级交互细节」约 47 秒一圈），每 0.1 秒检查一次：有没有元素露出一部分、另一部分被卡片边缘或标本内部的裁切容器切掉。已加入 GitHub Actions。来由见 [dev-log 014](../dev-log/014-catalog-states-check.md)：003 的排版卡片最后一步被切，当时只靠截图发现。

写新标本时的规矩：

- **目录尺寸**用 `@media (max-height:260px)` 单独处理（缩小、收紧间距、藏次要信息），详情页不受影响。卡片舞台：电脑 357×188，手机 348×216。
- **完全藏在外面**的东西（关着的抽屉、透明度为 0 的菜单）不算被切；**滑进滑出**途中短暂越界也不算，越界要持续 0.7 秒以上才报。
- **可滚动区域**（`overflow:auto/scroll`）里滚出去的内容不算被切。
- **故意被切**的元素（跑马灯轨道、视差山景、轮播唱片、缩放画面、甩出去的卡片）加 `data-clip-ok`，加在**会动的那个元素**上，不要加在整个舞台上，否则舞台里真被切的东西也查不出来。只在某段时间里故意出界的，就只在那段时间加（见 `card-swap` 的 `loose()`）。

失败时用 `--shots 目录` 把出问题的卡片截下来；报告里写明「哪个元素被哪个容器切掉」。
