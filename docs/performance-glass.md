# 雾白玻璃主题与加载优化

> 2026-09-07 更新：本文记录初版静态目录方案。用户明确拒绝以截图替换 UI 词典的核心动效，现已改为按视口运行的动态标本，见 [动态标本验证](live-specimens.md)。以下数据属于历史版本。

用户明确选择第三套雾白 / 墨黑配色，要求玻璃拟态，并反馈现网打开慢。

## 发现的瓶颈

- 原 Service Worker 的列表包含 314 个额外资源，约 14,027,242 字节。每次新版本安装会预下载整站，且任意请求失败会让整体安装失败。
- 原首页含 60 个 script 元素和 2,821 个 DOM 元素；目录里的标本会同时执行动画、定时器和翻译观察逻辑。
- 每个页面立即获取完整目录数据；外壳还需要独立 CSS 和 JavaScript 的网络往返。
- 本机一次公网 curl 测量中，连接 GitHub Pages 耗时 18.85 秒，首字节 19.28 秒，总计 19.88 秒。该等待主要发生在 TCP 连接阶段，与 CSS 复杂度无关。它不能用本地渲染优化数据来掩盖。

## 已实现

- 目录使用从实际标本生成的 118 组中英 WebP，共 236 张、约 1.81 MB；不在目录运行标本脚本。详情保留实际交互。
- 首页前三张预览随 HTML 直接提供，其余在视口附近 240px 才请求；固定舞台尺寸，无 JS 时有原生图片回退。
- 共享外壳 CSS 和 JS 随 HTML 提供，减少高延迟托管中的阻塞往返。页面参考详情才加载其专用 CSS；含交互标本的详情才加载翻译数据。
- 搜索和参考集首次使用时才获取完整目录；加入/移除参考与数量显示无需等待数据请求。
- Service Worker 仅预缓存不足 4 KB 的离线说明页；实际访问资源才入缓存。已缓存页面立即返回，并在后台更新。上限 160 个响应。
- 玻璃模糊局限在导航、命令面板和对话框。目录舞台与页面参考内部的小卡片不叠加实时背景模糊；手机命令面板关闭实时模糊。

## 相同条件下的本地测量

Playwright Chromium，1440×1000，150ms 网络延迟、200 KiB/s 下载、100 KiB/s 上传、CPU 4 倍降速，新浏览器上下文、关闭 Service Worker，加载后观察 2.5 秒。以下为各次单次实验记录，不是公网用户分位数，也不代表所有访问都能达到这些时间。

| 指标 | 修改前 | 最终实现 |
|---|---:|---:|
| FCP | 1296ms | 712ms |
| LCP | 1296ms | 792ms |
| loadEventEnd | 3709.8ms | 2056.8ms |
| 观察窗口内长任务累计 | 333ms / 3 次 | 0ms / 0 次 |
| 首页 script 元素 | 60 | 3 |
| DOM 元素 | 2821 | 1614 |
| 资源请求（不含 HTML） | 10 | 7 |

中间版本把前三张预览也延迟到 JS 后才加载，LCP 变成约 2.17 秒；最终将这些预览随 HTML 提供，恢复到 0.79 秒。这是实际首屏素材加载顺序的修正，不是隐藏 LCP 内容。

## 功能与缓存验证

- 1440px / 390px 覆盖首页、页面参考、风格、品牌目录和交互详情，无横向溢出、无 JavaScript 错误。
- 首次浏览不请求 catalog.json；打开参考集后正确读取资料，Markdown 含用户填写的项目说明；全局搜索 Linear 返回正确结果。
- 英文模式确实切换到英文预览，中文菜单搜索返回相关词条；Escape 从搜索输入框直接关闭对话框。
- 页面参考手机端仍可切换错误状态；实际详情代码未移到预览图中。
- 缓存配额写入失败的模拟验证通过：成功的网络响应仍然返回，不错误显示离线。
- 注册实际 Service Worker 后缓存已访问首页，断网回访 22ms 完成；访问未缓存页面显示「暂时离线」，而不是假冒首页。
- 242 个 HTML 文件与 192 个目录入口路径校验通过，236 张图片的尺寸和非空内容通过检查。
- `scripts/verify-performance.py` 加入 CI：限制目录脚本、禁止实时标本和阻塞样式往返、限制 HTML/gzip 大小，并禁止恢复整站 addAll 预下载。
- 设计检测器的动态图片属性提示属于构建模板识别限制，已通过生成产物、浏览器加载及无 JS 回退核对。原规范的灰绿配色与字号提醒由此次更新后的 DESIGN.md 和 sidecar 记录。

## 公网速度的边界

此次修复解决页面和缓存层的额外负担；首次与 GitHub Pages 建立连接的线路延迟仍可能存在。若目标是稳定降低该部分等待，需要 CDN / 边缘托管及相应域名配置，不能把本地实验结果宣传成已经修复源站网络。现有公网地址保持不变。
