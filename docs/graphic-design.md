# 平面设计栏目

## 定位（用户拍板 2026-11-18）

新增「平面设计」栏目，做成**「案例 + 手法」的拆解库**，不是单纯的作品集：每个案例是入口，拆出它用了哪些手法、版式和字体怎么安排、主色是什么，并给出让 AI 复刻手法的提示词。案例积累后，「手法」形成可筛选、可学习的词汇。

用户的三个决定：

1. **版权：选 A。** 公开页面放我们用代码复刻的「标本」和拆解，原作只放来源链接，不转载原图。（2026-11-18 已调整，见下方「策略调整」。）
2. **提示词：两种都给。** 一段给生图工具（讲画面），一段给写代码的 AI（讲版式结构）。
3. **案例来源：小红书链接为主，也有用户自己存的图片。** 图片案例需要附作者或来源，否则无法注明出处。

用户目前收集的类型，按数量从多到少：**海报 > 游戏平面设计（KV / PV 视觉）> 包装**。首页「类型」分类先按这三类建，后续按实际案例增加。

## 策略调整（用户拍板 2026-11-18，取代上面第 1 条）

用户看过 3 个虚构名字的复刻后认为效果不好，改为：

- **尽可能还原原作**：标本使用原作的真实名称、字标文字和版式，尽量贴近原作；
- **放上原作图片**：从收录笔记中截取原作画面，与复刻标本并排展示。

用户理由：网站不盈利，素材均为公开发布的宣传物料。

执行要求：每张原图注明原作方、年份和图源；「来源与许可证」页写明版权归原权利人、权利人要求即删除；原图压缩为 WebP，只截取原作画面，不带收录者的排版和文字。复刻依旧标注「代码复刻」，插画、摄影、角色画面不重画，用原图展示。

## 关键词分层（用户拍板 2026-11-18）

讨论「手法词汇不像行业术语」时理清了两层模型：**宏观层**是主义/流派/风格词（构成主义、Y2K、瑞士风格），**微观层**是单张画面的手法（斜线分区、图文穿插）。据此调整：

- **列表页关键词展示宏观层风格词**，详情页继续拆微观层手法；列表页原「手法词汇」版块删除，手法解释改为详情页手法标签的悬停提示。
- **与风格图谱解耦**：风格图谱针对网站/UI 风格，平面设计五花八门，只是恰好同类词。风格词是 `data/graphics.json` 里自由维护的词汇表 `styleTags`（15 词起步），不链接图谱页面、不校验图谱 ID。
- 词汇表构成（经 web 检索核实）：电竞主视觉大多没有教科书风格名，工作室自述只说「透视网格」「粗几何」这类描述；真风格名（构成主义、Y2K、瑞士风格、酸性图形）只在呼应属实、社区也这么归类时使用，其余用大白话描述词（大字排版、战术工业风、警示标识风……）。原拟的「未来主义」因无人这么称呼而弃用。
- 列表页「风格」下拉筛选用 `?style=` 参数；卡片标签、⌘K 搜索同步吃风格词。

## 命名规则（用户反馈 2026-11-18）

手法名称用大白话，不用行业黑话；行业叫法放进说明里。起因是「出血到边」读起来很怪，已改为「溢出画面」，同时把「单色底场」改为「满版纯色底」、「跨版式延展」改为「多尺寸延展」。

## 和现有栏目的关系

- **视觉风格**：已解耦（2026-11-18，见「关键词分层」）。平面设计自己维护风格词汇表，不链接风格图鉴。
- **Logo 图鉴**：独立栏目，不并入。
- **排版细节**（`typography-details`）等词条：在拆解中引用。

## 案例页结构

- 复刻标本（代码实现，标注「风格复现，非原作」）。
- **拆解开关**：网格线、字体层级、主色板、视觉焦点、留白，可逐层打开。
- 基本信息：类型、风格关键词（自由文本）、来源与作者、来源链接。
- 一句话点评：好在哪。
- 手法标签：悬停显示解释；底部汇总使用了相同手法的其他案例。
- 配色：色值可复制。
- 提示词：生图版 + 代码版，都要求「学手法，不复制原作」。
- 加入参考：进入全站参考集与导出。

首页按类型、风格筛选；与 Logo 图鉴一样按期记录来源。

## 复刻的边界（实施前需要知道）

- 代码能复刻的是**版式、字体、配色、图形元素和特效**；插画、摄影、3D 渲染这类画面内容，标本里用抽象的形状、渐变或剪影代替。游戏视觉通常以插画为主，标本重点放在构图、标题字效和信息层级上。
- 包装是立体物，标本以正面展开图为主，必要时加一个可旋转的 CSS 盒子。
- 标本是学习用的重新实现，不保证与原作一致；页面需注明。

## 实现（2026-11-18）

- 数据：`data/graphics.json`（期次、类型、手法词汇、案例）；原图：`assets/graphics/<slug>-<n>.webp`（及 `@2x.webp`）；标本：`demos/graphic/<slug>.html`；拆解图层：`assets/graphics.js`。
- 标本只做标记：`data-ov-type`（字体层级）、`data-ov-focus`（视觉焦点）、`data-ov-space`（留白）、`.gd-grid`（网格），图层由页面统一绘制，新案例不必重写图层代码。
- 按「策略调整」，标本尽量还原原作（原名、原字标、原构图），详情页先放原图，再放代码还原；写明原作设计方、年份、图源，并链接收录笔记。
- 横竖混排（用户拍板 2026-11-18）：列表页是瀑布流，封面按原图比例；详情页首图是竖图时左右分栏，是横图时上下排列，其余图按比例并排。
- 清晰度：小红书原图最大约 1262 px 宽。能找到官方或设计方大图的换大图（第 1 期 10 个案例里 9 个已换，2026-11-18）；其余用 Real-ESRGAN 生成 2 倍图，只在高清屏通过 `srcset` 加载，并在图注标「AI 放大 2 倍」。列表页封面标准版已够 900 px 宽时不再加载 2 倍图。
- 第 2 期《再电离 版式设计与拆分》（蓝山拉菲，2026-11-16）1 个海报案例 `reionization`：作者本人发的作品，原图是 8534×4500 的设计稿，图注标「作者原图」（新增来源类型 `author`，2026-11-18）。作者自己给了逐层拆分，标本按同样顺序做成 5 步（文字 → 网格与代码 → 星云与标注 → 成稿 → 酸性版）。
- 第 1 期《电竞赛事背后的优秀视觉设计》（YK的设计漫游，2026-10-28）共 10 个案例：Worlds 2022、Dota 2 TI 2025、VCT 2023、CS2、MLBB 十周年、PUBG Mobile、Fortnite FNCS、Apex Legends、街头霸王 6 CAPCOM CUP、THE FINALS。用户确认样式「对味了」（2026-11-18）。

## 第 4–13 期与新规矩（2026-11-20）

用户 2026-11-20 一次发来 10 条平面设计笔记（另有 1 条交互动效进了 UI 词典，见 dev-log/015），拍板：

- **视频教程收成案例**：先从视频里截成品帧给用户看，用户同意后收（霓虹发光、故障风、离解复合 PV、《沉沦在世界树之下》四条全收）。教程步骤写进拆解和提示词，标本按教程顺序分步。视频帧的图注写「截自作者视频」（新来源类型 `video`，见下）。
- **趋势视频每种风格一个案例**（2027 趋势两条视频，共 8 种风格）。原图用收录者的整张趋势看板截图（看板本身就是趋势内容，这是唯一一次例外于「不带收录者排版」）；标本不复刻看板，而是用代码做一张这种风格的示范海报，标题自拟。案例数据加 `"specimen": "style-demo"`，详情页小标题因此显示「风格示范与拆解」。
- 新类型 `brand`（品牌视觉），首例 BISON ENERGY。
- 新风格词 9 个：故障风、狂野艺术风、弥散渐变、瑞士朋克、复古未来、字体即图形、新地域主义、触感材质、新粗野主义。
- 新来源类型 `video`：截自设计师本人发布的视频（`export_originals.py --origin video`）。和 `note`（截自别人的收录笔记）、`author`（设计师本人发的原稿文件）区分开。
- 桌面详情页的标本区固定 520px 高、超出部分被裁掉：标本连同分步按钮必须放得下，`test-graphics-layout.py` 已加检查（起因：蒙太奇标本 633px，上线后顶部和按钮被切）。

## 收录流程（2026-11-18 沉淀）

用户确认第 1 期效果后，把流程固化成脚本和检查。新案例照下面走，Claude 用项目 skill `.claude/skills/add-graphic-case/` 执行同一流程。

1. **下载笔记原图**（存在仓库外，原图不进仓库）：
   ```bash
   ~/.local/share/codex-tools/XHS-Downloader/.venv/bin/python \
     scripts/graphics/fetch_xhs_note.py "<分享链接>" ~/.local/share/codex-data/xhs-graphic/<批次>
   ```
   失败多半是链接过期：要一条带 `xsec_token` 的新分享链接。用户直接发图时跳过这步。
2. **从合集页裁出原作**：
   ```bash
   python3 scripts/graphics/crop_originals.py ~/.local/share/codex-data/xhs-graphic/<批次>/download /tmp/<批次>-crops
   ```
   **必须打开 `contact-sheet.jpg` 逐张看**：只留原作本身，去掉收录者的标题和说明；裁错的调 `--top/--bottom/--skip` 重跑。
3. **找官方大图**：Steam 游戏用 `cdn.cloudflare.steamstatic.com/steam/apps/<appid>/library_600x900_2x.jpg`、`library_hero.jpg`；其他看官方新闻稿、品牌页、设计方作品集。找到就用官方图，找不到用笔记截图。
4. **写案例数据**：在 `data/graphics.json` 加案例（期次、类型、风格关键词、手法、配色、四层拆解说明、两组提示词、署名和图源）。手法名用平实中文（见「命名规则」）；风格关键词从 `styleTags` 词汇表里选，没有合适的就加一个新词（中英双语，词表见「关键词分层」）。
5. **导出原图**：
   ```bash
   python3 scripts/graphics/export_originals.py <slug> 图1.png 图2.png …          # 笔记截图，自动 AI 2 倍
   python3 scripts/graphics/export_originals.py <slug> 官方图.jpg --origin official --start 3
   ```
   第一张是首图，决定详情页版式（竖图分栏、横图上下）。脚本写好宽高和来源，新图的图注是 `TODO`，要补成中英文。
   脚本按尺寸自动处理：长边 ≤ 1400 的（笔记截图、小官方图）原样保存并生成 AI 2 倍图；1401–1819 的原样保存、不做 2 倍图；≥ 1820 的（官方大图）标准版缩到长边 1400，2 倍图直接用原图像素缩出，不经过 AI。
   用了官方或设计方的图，要在案例里填 `sourceUrls`（图片来源页面），详情页署名行会显示成链接。
   来源类型：`note`（截自别人的收录笔记）、`official`（官方或设计工作室发布）、`author`（设计师本人在笔记里发的原稿）、`video`（截自设计师本人的视频）。
6. **生成列表页封面**：`python3 scripts/graphics/make_covers.py`。列表卡片最宽只有约 440 点，直接发 1400px 原图等于浪费 4 倍流量；脚本按 450 / 1000px 两档生成 `<slug>-cover.webp`，画质与原图无差（实测色差 1.38/255）。换过原图就要重跑，`validate-data.py` 会检查封面是否过期。
7. **写还原标本** `demos/graphic/<slug>.html`：照原图还原版式、字标和配色；插画和照片用形状代替。给标题加 `data-ov-type`，视觉焦点加 `data-ov-focus`，留白区域加 `data-ov-space`，网格画在 `.gd-grid`；有多种尺寸或物料的，做切换按钮并在切换时派发 `gd:layout`。
8. **检查**：
   ```bash
   python3 scripts/validate-data.py          # 字段、图片宽高与文件一致、2 倍图恰为 2 倍
   python3 build.py && python3 scripts/verify-site.py site
   python3 scripts/test-graphics-layout.py site --engines chromium,webkit   # 不变形不裁切、高清屏加载 2 倍图、无横向滚动、拆解标记落在画面内
   ```
   再截 2000 / 1440 / 390 三档宽度看一眼，对照原图检查还原度。
   海报里的文字是作品的一部分，不随网站语言翻译：站点的示例翻译会跳过 `[data-gd-canvas]` 内的文字（2026-11-18，起因是 Reionization 标注里的「Active」被译成「活跃」）。
   手机上标本区高度跟内容走；会切换横竖版的标本要自己在手机上预留最高版式的高度（见 `the-finals.html`、`cs2-store.html`），测试会检查空白不超过 60px、切换时高度不跳。
