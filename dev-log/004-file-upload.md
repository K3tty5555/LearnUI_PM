# 004 文件上传（5 种入口）

## 目标

用户 2026-11-17 给出小红书视频《常见的文件上传方式有几种？》（Sue的AI知识库，2026-10-20，93 秒，有口播），要求「这个也弄一下」。

视频讲网页上传文件的 5 种入口，以及各自的要点：
- 本地文件上传：说明格式和大小，允许移除后重选；
- 拖拽上传：拖拽区域有明确反馈，保留点击选择；
- 粘贴上传：显示缩略图、可移除、能继续写文字；
- 拍照上传：先预览，支持重拍和确认，保留相册入口；
- 链接导入：校验能否访问，失败或没有权限时说明原因。

结论是「先看文件在哪里，再选上传方式，也可以组合多种入口」。

## 关键决策与踩坑

- **做成一个词条、五个标签，而不是五个词条。** 视频的重点是「按文件在哪里选择入口、可以组合」，放在一起对比更符合这个意思。已有的「拖放」词条讲的是通用的拖放交互，不讲上传，所以不重复。
- **链接导入不能真去下载别人的文件。** 浏览器跨域读取文件通常会被拦，正确做法是由自己的服务器去取，这一点写进了代码符号表和 prompt。标本只用 `<img>` 预览图片地址，能加载就显示，加载失败或 8 秒超时就给出原因。
- **吸取 003 的教训，目录卡片检查了全部状态。** 第一版在目录尺寸下，本地上传的两个文件把列表撑出了卡片底部。改为目录尺寸只显示最新一项后，在 Chromium 和 WebKit 里各跑完整一轮（约 24 秒），每 0.5 秒检查一次，5 种入口的所有元素都没有超出卡片。
- **输入无效链接时显示的是旧消息。** 网址输入框是 `type="url"`，浏览器自带的校验先拦下了提交，我写的「请输入以 http(s):// 开头的完整链接」根本没执行，状态栏还停在上一次的失败原因。给表单加 `novalidate`，由标本自己校验和提示；修复前后各跑过一次测试对比。
