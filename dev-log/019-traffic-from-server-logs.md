# 019 用服务器日志统计浏览量、访客和 IP 属地

## 目标

用户 2026-11-22 问：网站的 UV、PV 能统计到吗，用户的 IP 属地呢。本篇是调查记录，没有改动网站。

## 结论

**都能，不用给网站加任何统计代码。** 网站放在用户自己的服务器上，服务器每接待一次访问记一行日志（时间、路径、状态、访客 IP、浏览器身份）。日志只读拷回本机分析，访客 IP 不发往任何第三方。

上线头 4 天（2026-11-18 23:22 至 11-22 23:22）的实际情况：

| | 次数 | 来源 IP |
|---|---|---|
| 发往 `/UIUX` 的请求 | 6987 | — |
| 其中网页请求 | 3103 | 990 |
| 机器（爬虫、扫描器、链接预览） | 2866 | 955 |
| 像真人的浏览器 | 237 | 35 |
| 其中用户自己（含主会话当天用有界面浏览器做的测试） | 179 | 3 |
| 外部 | 58 | 32 |

- 外部 32 个 IP 里，认真看过的（看了 2 个以上不同页面）4 个：一个 iPhone 一分钟内点了 5 个栏目、与用户当时的出口同地区，几乎可以肯定是用户自己的手机；两个 Windows 浏览器（隔天又回来）是真的访客；一个美国 Windows 浏览器只看了首页但触发了搜索，不能确定。
- 其余 28 个只打开过一次首页，无法确定是人还是会执行脚本的机器。其中 8 个是 11-20 05:26–05:28 两分钟内出现的同省 iPhone、浏览器身份完全相同，可以确定是机器。
- 11-19 09 点一小时的「681 次浏览、500 多个访客」是爬虫：658 次自称 Windows 上的 Chrome 94（2021 年），133 次自称 2019 年的 iPhone iOS 13.2.3。只按浏览器名字过滤会把它们当成访客（第一版报表因此报出「533 个访客」）。

## 做法

工具在本机 `~/.local/share/learnui-traffic/`（仓库外，不含访客数据）：

1. 拉日志：`ssh sg-server 'cat /var/log/nginx/access.log'` 等（当前、昨天、更早的 `.gz`）。`ubuntu` 用户在 `adm` 组，不需要 sudo。服务器日志每日轮转、保留 14 天。
2. `analyze.py`：解析、判定真人与机器。
3. `geo.py`：只读查询离线 IP 库 ip2region（`geo/ip2region_v4.xdb`，11 MB，数据日期 2026-11）。库里是 `国家|省份|城市|ISP`。
4. `report.py`：每天的浏览量 / 访客、用户自己的访问、外部访客属地、机器属地。`self-ip.txt` 存当前出口地址（`$SSH_CLIENT`），用来去掉用户自己。输出只有汇总，不打印完整 IP。

**真人判定用两个骗不了的信号**，而不是浏览器名字：

- 浏览器身份是近两年的版本（伪装的爬虫爱用多年前的版本）；
- 这个 IP 还取过「只有页面脚本跑起来才会去取的东西」（图片、字体、标本数据、service worker）。只下载网页本身的是机器。

剩下的再按深度分开报：「认真看过」（2 个以上不同页面，或触发过搜索）和「只打开一次首页」，后者永远不计入前者。

属地按国内 App 的习惯显示：国内到省，国外到国家。

## 关键决策与踩坑

- **第一版按浏览器名字过滤，报出 533 个访客**，查了每个访客的画像才发现是伪装的爬虫。教训：访问量里机器占九成以上时，「像浏览器的」不等于「人」。
- **属地库对云主机和代理不准**：用户的新加坡服务器被标成香港。普通访客（家庭宽带、手机流量）基本准。属地是 IP 的登记地，不是人的位置；走代理的访客显示代理所在地。
- 这个 IP 库只有 IPv4。本站日志里目前没有 IPv6 访客；以后有的话属地显示「未知」。
- jsDelivr 上这个库的路径改过名：`data/ip2region.xdb` 是 404，现在是 `data/ip2region_v4.xdb`，文件格式是第 3 版。没有执行下载来的任何代码，查询器是照公开格式自己写的。
- 报表第一版的合计行把每天的访客数直接相加，比去重后的总数还大；已改为去重。
- 「触发过搜索」这个信号不可靠（统计方式有问题），没有用它下结论，判定主要看访问深度。

## 局限

- 看不到页内行为：搜了什么词、点了哪个案例、停留多久。网站是纯静态的，这些不会发到服务器。要统计得在网页里加统计脚本。
- 浏览量按请求算：悬停预取会让它略偏高，离线缓存会让它略偏低；访客按 IP 算，同一网络下几个人算一个，换了网络会重复计。
- 日志只留 14 天，要留历史得定期取回存档。

## 追加（2026-11-23 随时可看 + 自动存档，用户同意第 1、2 项）

用户答复「1/2 可以做」：报表留作随时可跑；设定时任务定期取回日志。页内行为统计不做。

- **随时可看**：`~/.local/share/learnui-traffic/traffic.sh [--days N]`——先取回并归档，再出报表。用户问访问情况时运行它，用平实中文读回结果。
- **自动存档**：macOS 用户级定时任务（LaunchAgent `local.learnui.traffic-archive`，`~/Library/LaunchAgents/` 下）每周一、周四 10:17 运行 `archive.sh`。不用 sudo；已手动触发验证一次，正常退出。停掉：`launchctl bootout gui/$(id -u)/local.learnui.traffic-archive`。没有用 Claude 自带的定时任务，它 7 天后会过期、且只在 Claude Code 开着时才触发。
- **归档方式**：`archive.py` 用一次 ssh（`cd /var/log/nginx && tar -czf - access.log*`）取回服务器全部日志，按每行日期归档。已结束的日子写进 `days/` 一次、不再改动；当天写进 `partial/`，每次覆盖，过完那天再进 `days/`。不做逐行合并，所以不重复也不丢失；两次运行间隔不超过约 12 天即可（服务器留 14 天），超出的日期报表会报 WARNING。已与 11-22 手工拷贝的那份逐行比对一致，每天首尾时间相接。
- **去掉用户自己的访问**：每次运行记下当前出口地址到 `self-ip.txt`（用户的出口会变，一天就见过两个），加上「浏览器身份与本人相同且访问了 3 个以上栏目」的判断。手机流量认不出来，会算成外部访客。
- 报表：按显示宽度对齐；常用国家名译成中文；`--days N`。

### 踩坑

- tar 里的 `.gz` 成员要先解压再按行读：第一版把压缩字节当文本，报出 3978 行「读不出日期」，较早的 4 天没归进去。
- 远端通配符在远端的用户主目录展开，`tar -C 目录 access.log*` 找不到文件，要先 `cd`。
- 合计行把每天的访客数相加，这个错犯了第二次（11-22 改过一次，重写时又写回去）；现在是去重后的数。
- 用脚本批量替换代码时，把一句提示上面的 `if` 一起切掉了，于是每次都打印「没有 self-ip.txt」。改完代码要把输出逐行读一遍。
- 服务器日志本身有完全相同的重复行（同一秒同一 IP 同一请求），所以不能靠「去掉重复行」来合并快照。
